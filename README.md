# Doubao Web Toolkit

Chrome/Edge Manifest V3 浏览器扩展，专门服务 doubao.com / dola.com 网页版。

## 功能（MVP 首批，全部可运行）

| 功能 | 状态 | 说明 |
| --- | --- | --- |
| 调试面板 | ✅ | 右下角⚙按钮（或弹窗「调试面板」）→ ① 可折叠「使用说明」（**表格**：区域 \| 怎么用）；② DOM 选择器表：直接编辑并「保存」到 `dwt_selectors`，无需改代码，「重置」恢复默认；③ 实时状态（replyState / captcha）；④ 「元素选择模式」：悬停高亮 → 点击元素自动生成 CSS 选择器 → 复制并回填到所选字段，ESC 退出 |

| 说明文本表格化 | ✅ | 面板里的解释性文案不再是一整段「·」串文：批量面板「?」使用说明与调试面板「使用说明」按**分节 + 表格**渲染（分节标题条 + 键列 `nowrap` 加粗 + 值列 `pre-line` 支持多行），归属一眼对上；数据/可编辑 tip（重命名、前置词、单条内容、回复全文）仍是文本模式。表格走 `createElement` + `textContent`（不用 innerHTML），深色下表底/边框/字色全走 `--dwt-*`，分节标题深色就地提亮为 `#7fb0ff`（实测 7.06:1） |
| 对话导出（Markdown + JSON） | ✅ | 入口在**右下角 🧰 菜单**（📄 导出 Markdown / 📦 导出 JSON），不在弹窗里。导出时会自动向上滚动把**整段历史对话**都收集齐（不是只有屏幕上那几条），采集中右下角有进度条和「取消」按钮，结束后自动回到原来的滚动位置。导出的顺序就是真实对话顺序：用户一句、AI 一句、用户一句、AI 一句，不会把用户的话全堆在前面。Blob 下载到本地 |

| 提示词快捷条（快捷回复） | ✅ | 输入框旁一个「💬 快捷回复」按钮，滑过/点击向上滑出**分组**面板，点条目即写入 ProseMirror；面板内 ✎ 可就地增删分组与条目（或 JSON 批量导入导出），配置存 `dwt_prompts` |
| 外观跟随（深色/浅色） | ✅ | 读**豆包自己的外观设置**（`html[data-theme]` → `localStorage['dbx-web-theme']` → 页面背景亮度）实时跟随，切外观后 ≤1.5s 翻转全部注入 UI：面板走 `--dwt-*` 变量、收藏高亮关键字压回黄底深字、导航条平行配色由 `dwt:themechange` 重算；系统偏好只作最后兜底（本机「系统深色 + 豆包浅色」是常态，信系统会判反） |
| 自动滚动 + 悬浮⬇按钮 | ✅ | MutationObserver 监听新回复，用户接近底部时自动滚 |
| 联网来源标注 | ✅ | 扫描 AI 回复外链 → 解包 `link.wtturl.cn` 跳转 → 域名可信度分级（高/中/低）→ 回复旁挂「🔗 来源 N」徽标，点击展开来源面板 |

| 对话目录搜索 | ✅ | 导航条顶部搜索框，按关键词实时过滤提问目录项 |
| 开发热重载 | ✅ | **仅开发用（默认关闭）**：改动源码后自动重载扩展 + 刷新已打开的豆包页面，无需手动去 `chrome://extensions` 点「重新加载」 |


## 安装（开发者模式）

1. `git clone https://github.com/jycoder666/doubao-web-toolkit.git`
2. Chrome 打开 `chrome://extensions` → 右上角开发者模式 → **加载已解压的扩展程序** → 选中本项目目录
3. 打开 `https://www.doubao.com/chat`
4. 页面上会出现：
   - 右下角「⚙ 调试」蓝色按钮 → 点开调试面板
   - 右下角「💬 快捷回复」按钮（滑过/点击滑出分组面板）
   - 右侧「📌 导航」卡片（检测到豆包原生导航轨道时直接接管该轨道，豆包刻度内容隐藏）
   - 左下角「⬇」悬浮按钮
   - AI 回复旁的「🔗 来源 N」徽标（联网来源标注）
   - 开启「对话管理」后，左下角出现「🗂」入口按钮
   - 开启「对话摘要」后，右下角出现「🧾」入口按钮
   - 右下角「📑 本回复大纲」面板（只在当前回复含标题时出现；无标题的纯文本回复不显示）
   - 右下角「🧰」菜单里还有「📄 导出 Markdown」「📦 导出 JSON」两条导出入口
5. 扩展图标点开 = popup（**只留功能开关**：来源标注/对话管理/阅读标记/对话摘要/回复大纲/语料高亮/推荐屏蔽/背景氛围/悬浮便签/宽屏折叠/视觉关键词/英语拆行/论文提示 + 立即扫描来源 + 调试面板 + 配置页；批量与导出已迁到右下角菜单，弹窗里不再有这两块）
6. 扩展图标右键 → 选项 = 配置页（功能开关 + **DOM 选择器覆盖可视化编辑器** + 批量问答的间隔/超时；批量问答的题目队列在页内「📋 批量问答」面板里填，不在配置页）
7. **每个工具开关都带「ⓘ」提示**：配置页悬停功能名后的 `ⓘ`、弹窗悬停工具按钮，即可看到该开关**开启后会发生哪些变化**（分点说明），无需试错

## 开发热重载（改代码免手动刷新）

默认关闭。**开发时**在配置页 → 「开发」→ 勾选「开发热重载」并保存，即可：

- 每 1.5 秒对扩展自身源码文件做一次内容指纹比对；
- 检测到任意源码文件被保存/修改后，**自动刷新所有已打开的豆包标签页**，并**自动重载扩展本身**；
- 无需再手动去 `chrome://extensions` 点「重新加载」，也无需手动刷新页面。

实现：`background/hot-reload.js`（零依赖）。原理是 MV3 没有「文件变化」事件源，故用
`chrome.runtime.getPackageDirectoryEntry()` 直读磁盘文件（回退 `fetch(no-store)`）计算
FNV-1a 指纹轮询比对；因 MV3 Service Worker 约 30s 空闲即被终止，模块内置 20s 保活心跳
（调用 `chrome.runtime.getPlatformInfo`）以维持轮询。

> 注意：开启后会周期性读取扩展文件，属开发用途，**正式使用请保持关闭**。

## 批量输入（用户原创）

界面入口：右下角工具栏 🧰 → **📋 批量问答**（页面内面板，队列化逐条状态）。
题目队列就在这个面板里填（**表格** 逐条编辑 / **JSON** 整包编辑，两个视图可切换）；
**选项页**现在只留「间隔 / 超时」两个参数，不再有单独的模板区（模板区已被右下角面板取代）。

面板要点：
- **多任务**：面板顶部下拉切换任务，`＋ 新任务 / 重命名 / 复制 / 删除`。**同一时期只有一个任务能进行中**：
  有任务在跑时下拉与这四个按钮全部禁用（`start()` 另有一道显式拒绝，不靠按钮禁用兜底）。
  - 存储：任务索引 `dwt_batch_tasks_v1`（含 `activeId` 与各任务进度摘要）+ 每任务队列键 `dwt_batch_task_q_<id>`；
    `dwt_batch_queue_v2` 继续写，作为**活动任务镜像**（popup 与旧流程兼容）。
  - 旧数据首次升级自动成为「任务 1」，内容不丢；「复制」得到的是**可再跑模板**（题目/附件/前置词/会话照搬，
    上次运行的 status/reply 重置）；「删除」需点两次确认（4 秒内有效），且至少保留一个任务。
- 队列逐行编辑（文本 + 附件），每行独立状态徽标（待发送/发送中/等回复/成功/失败/超时/约束未满足/已暂停/已跳过）；
- 全局前置词、发送间隔、回复超时；运行中锁定编辑，避免「跑一半改队列」错位；
- 每条可设**回复约束**：`plain`（回复须纯文本）/ `image`（回复须含图），不满足则该条标「约束未满足」并暂停，
  点「继续下一条」跳过该条往下跑；
- 队列与断点存 `dwt_batch_queue_v2` / `dwt_batch_breakpoint`（多任务下另有每任务键），刷新或重注入都不丢；
- 图片/附件条目见上方[已知限制](#已知限制图片附件条目)：插入失败会显式失败并暂停，不会假装成功。

**JSON 格式**（面板 JSON 视图的根是一个对象，`items` 里一条一个问答）：
```json
{
  "prefixOn": false,
  "prefix": "",
  "sessionId": "",
  "sessionUrl": "",
  "items": [
    {"text": "请帮我写一篇关于 AI Agent 的周报"},
    {"text": "把上一条翻译成英文"},
    {"text": "总结当前对话的三条结论"}
  ]
}
```

**表格视图**（默认视图）：一行一条，左边改内容、右边看状态徽标与回复，与 JSON 视图同源
（改完 JSON 要点「应用到队列」才生效；反向可点「从队列刷新」拉回当前队列）。

执行：右下角 🧰 → 📋 批量问答 → **从头开始**（或「从断点继续」）→ 逐条输入发送 → 等回复
（`data-streaming="false"`）→ 下一条。
**检测到验证码自动无限暂停**，人工处理完后在面板点「继续」（放行并走下一条）。

## DOM 选择器（2026-10-16 豆包页面实测）

| 选择器 | 默认值 | 说明 |
| --- | --- | --- |
| 输入框 | `.ProseMirror` | tiptap contenteditable 编辑器 |
| 发送按钮 | 优先 `bg-g-send-msg-btn-bg`，兜底特征匹配 | 输入框空时发送按钮不存在，用 `waitForSend()` 200ms 轮询 |
| 回复中标识 | `[data-streaming="true"]` | 豆包用 data-streaming 属性，不用 thinking/streaming class |
| 用户消息 | `[class*="bg-g-send-msg-bubble-bg"]` | |
| AI 回复 | `[class*="conversation-message-content-padding-right"]` | 来源标注以该容器为根扫描外链 |
| 验证码 | `[class*="captcha"], [class*="verify"]...` | 多 selector 兜底 |
| 侧栏会话项操作按钮 | `[data-sidebar-item-actions="true"]` | **hover-only**（默认 opacity:0），需先派发 `mouseover` 触发渲染 |
| 外链跳转包装 | `link.wtturl.cn/?target=<urlencoded>` | 豆包把所有 AI 回复外链包了一层跳转，取真实域名须解包 `target` 参数 |

所有选择器在**调试面板**里可查看/编辑/保存到 storage。

## 合规声明

**不做**：
- 去水印 / 无水印下载（违反 AI 标识办法）
- 逆向豆包 API / 中转反代 / 多账号轮询（违反平台协议与计费规则）
- 自动答题 / 伪造 AI 水印

**做的**：纯 DOM 层操作，零豆包 API 调用；单账号、手动触发。

## 技术栈

- Manifest V3（MV3 content scripts **不支持 ES Module**，全文件用传统 IIFE + `window.dwt` 全局命名空间）
- 零构建、零 npm install、直接加载
- chrome.storage.local + （预留）IndexedDB
- 核心路径全部在 content scripts（绕过 MV3 Service Worker 30s 生命周期限制）

## 为什么不做油猴脚本

- MV3 原生支持更稳定
- 权限声明透明（manifest.json）
- 不依赖宿主扩展的权限系统

## 已知限制：图片/附件条目

豆包对**脚本触发**的附件插入一律免疫 —— 合成 `paste`、`input.files`+`change`、`input`+`change`、`drop`
四条路径实测都不会让输入区出现上传预览。因此批量问答的图片/附件条目**不会**静默降级成纯文本发送：
插入校验失败即标 `失败` + 原因「附件未能插入输入框…」并暂停（`⚠ 附件插入被拒, 已暂停`），
避免「带图提问」被当纯文本发出去、模型只能瞎猜答案。文本条目不受影响。

## 已知限制：导出时的消息合并

豆包网页不暴露每条消息的稳定 id，滚动采集只能靠「角色 + 正文前 500 字」当身份标记。
代价是：你连发两条**完全相同**的话（或两条长文开头 500 字一样），导出时会被合并成一条。
其余消息不受影响，顺序也始终正确。
